# Life Price Vercel 静态托管迁移设计

## 目标

将 Life Price V1 从当前 Sites 托管迁移到 Vercel 公网地址，避免 `chatgpt.site` 边缘安全策略导致的访问拦截。

## 范围

- 保留现有页面、交互、视觉、计算规则、测试和 localStorage 数据结构。
- 不增加登录、后端、数据库、AI、分析、PWA 或其他 V1 外功能。
- 只调整构建命令、静态导出配置和 Vercel 部署配置。
- 新站点验证成功前保留原站点，不执行删除或下线。

## 技术方案

项目继续使用 React 19、Next.js App Router 和 TypeScript。生产构建切换为 Next.js 静态导出，生成可由 Vercel CDN 直接托管的静态文件。应用所有状态仍只在浏览器端运行；收入与消费数据不会进入 Vercel 服务端。

本地开发保留现有可用预览方式，避免托管迁移影响当前开发体验。Vercel 使用独立的构建命令和输出目录；不再依赖 Sites 的 Cloudflare Worker 运行时完成新站点发布。

## 数据流

浏览器加载静态资源后，Life Price 继续直接读取和写入当前域名下的 localStorage。由于浏览器按域名隔离 localStorage，原 `chatgpt.site` 域名中的已有数据不会自动出现在新的 `vercel.app` 域名中。V1 不新增跨域迁移工具。

## 错误处理

- 静态构建失败时不发布。
- Vercel 登录或授权失败时保留本地代码和原站点，报告具体阻塞点。
- 部署成功但线上检查失败时不宣称迁移完成，继续定位平台配置或资源路径问题。
- 不在项目文件或 Git 配置中保存 Vercel 访问令牌。

## 验证

- 运行现有 19 项自动测试。
- 运行 TypeScript 与 ESLint 检查。
- 完成 Next.js 静态生产构建并确认入口文件存在。
- 在新公开 URL 上检查首次设置、价格换算、使用成本、两种决策、历史记录、设置修改和本地月份统计。
- 检查移动端宽度、控制台错误和页面刷新后的 localStorage 持久化。

## 完成标准

新的公开 Vercel URL 无需登录即可打开，核心闭环与当前版本一致，自动验证通过；原 Sites 站点保持不变，除非用户之后明确要求下线。
